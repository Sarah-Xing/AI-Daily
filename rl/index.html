  1. 机构：巴赫切谢希尔大学
    核心价值问题：RLVR 里到底该用全量微调还是 LoRA？大家只看秩和参数量，忽略了更新的几何结构，导致高秩 LoRA 会突然崩掉。
    方法：在统一冷启动 GRPO 流程下扫 LoRA 秩，发现 DeepMath-Hard 上 r=64 时准确率 73.1%、r=128 时骤降至 4.7%（秩坍缩）；对比之下 DoRA 与 QuanTA 在更宽优化区间内保持稳定、只更新不到 0.6% 的参数就接近全量微调；谱分析显示坍缩的 LoRA 更新能量集中在极少数方向。
    为什么值得看：给做 RLVR 的人一个直接可用的避坑结论——别只调秩，要看更新结构；结构化 adapter 是更稳的省参数路线。

    Structure Over Scale：RLVR 里的秩坍缩与结构化 adapter

    关键词：RLVR、LoRA、秩坍缩（rank collapse）、结构化 adapter（structured adapters）、DoRA

  2. 机构：南洋理工大学、亚马逊 AGI
    核心价值问题：无 critic 的 RLVR 给 response 里每个 token 同样的 advantage，但真正决定成败的只是少数“分叉点”token，现有按熵加权的启发式量不准 token 的实际影响。
    方法：把 token 的影响形式化为 forking value（下一 token 选择带来的成功概率方差），发现它可分解为分叉后果与分叉概率，而后者可由 softmax 直接得到、且随 token 在 response 内的熵秩指数衰减；据此设计 CreditFilter，按熵秩指数窗口给 token 加权，无需额外前向。
    为什么值得看：在 Qwen3-8B-Base 上比 DAPO 在 MATH500 高 7.7 分、AIME24/25 高 10.5/9.1 分，改动小、即插即用。

    CreditFilter：给 RLVR 的 token 按分叉价值加权

    关键词：RLVR、token 信用分配（token credit assignment）、分叉价值（forking value）、CreditFilter、数学推理（math reasoning）

  3. 作者：Zhe Dong、Fang Qin
    核心价值问题：RLVR 训练里，把采样文本解码再重编码可能训到同一字符串的不同 token 序列、奖励却一样；这个重 token 化会把更新推多远、方向是否一致，没人量过。
    方法：从同一 checkpoint 对比同一批 rollout 的规范更新与切分 token 后的更新：Qwen2.5-0.5B 三位数加法上，约每 25 个 token 切一个，更新位移达到换一批数据的 0.556 倍；比例随切分比例上升、且与切哪些 token 有关；同一 checkpoint 内不同 batch 的位移方向一致；还在表格模型里证明了除零梯度步外、不同 token 化下的全梯度步不可能一致。
    为什么值得看：一个容易被忽略的 RLVR 实现细节，实测影响量级接近换 batch；做 RLVR 训练 pipeline 的人值得检查自己的编解码路径。

    重 token 化会把 RLVR 更新推多远

    关键词：RLVR、重 token 化（retokenization）、训练稳定性（training stability）、token 序列（token sequences）、实现细节（implementation details）

  4. 机构：伊利诺伊大学厄巴纳-香槟分校、纽约大学、耶鲁大学
    核心价值问题：outcome reward 只给整条轨迹一个分数，步骤级信用分配通常要步骤标签、学 critic 或请 LLM 当裁判，成本高。
    方法：把通用决策模型（回答 yes/no 问题并给出概率）零样本转成通用过程奖励模型 DM-PRM：每步问一个问题、把标准化答案加进 advantage；无需步骤标签、微调或 critic，可插进任何策略梯度方法。
    为什么值得看：Qwen2.5-1.5B 上 GRPO 在 ALFWorld 提升 20 多分、WebShop 提升 10 多分，超过 critic 版 PPO 与 GiGPO 等基线；一个模型、一个问题模板就能跨环境复用。

    DM-PRM：决策模型零样本变过程奖励模型

    关键词：过程奖励模型（process reward models）、决策模型（decision models）、DM-PRM、零样本（zero-shot）、agent 训练（agent training）
